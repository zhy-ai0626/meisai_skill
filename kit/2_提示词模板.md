# 美赛 MCM/ICM 提示词模板

装好 skill 后直接说"开始美赛建模"即可走 10 阶段流程；下面这些是**不装 skill 也能用**的独立提示词，
或在流程中插入某个专项动作时用。

**结构**：0（六题预扫 + 选题）→ 1（单题深挖）→ **1B（按题型深挖，六选一）**→ 2（求解与呈现）
→ 3（Summary Sheet）→ 4（letter/memo）→ 5（终审）→ 6（纠偏）。

**用法约定**：`【】` 里替换成你的实际情况；`> ` 开头的是说明，不要粘进去。
所有依据都可在本仓库 `competitions/mcm/` 里查到（数字来自 279 篇 O 奖论文，见 `empirical.json`）。

> **用这些提示词就是在用 AI。** 按 COMAP 政策，把每次实质性使用记进 `decision_log.compliance.ai_usage`
>（或至少保存 query 与 output），最后生成 Report on Use of AI。

---

## 0. 总起：开赛后第一条指令

```
你是美赛（COMAP MCM/ICM）的建模顾问。我给你 A–F 六道题的题面，请完成：

1. 逐题抄录题面末尾 "Your PDF solution ... should include" 段：除标准件（Summary Sheet、
   目录、解答、参考文献）外还要什么（letter / memo / report），写给谁、几页、有什么限制。
   原文照抄，不要概括。
2. 逐题列出：Task 清单（按题面编号）、数据来源（题给 / 需自行找公开数据，列 2–3 个候选来源）、
   题面对模型形式的硬性要求（如 "will not satisfy this problem's requirements" 这类句子，原文照抄）。
3. 逐题判定题型（六选一，题号不是题型）：
   continuous_dynamics（ODE/PDE/机理）| discrete_optimization（调度/选址/分配）|
   data_inference（从数据估计/预测）| network_systems（网络/系统/流程）|
   evaluation_policy（评价/政策比较）| simulation_stochastic（元胞/Agent/蒙特卡洛）
   并给出判定依据（引题面原话）。
4. 按「团队方法匹配 / 数据可得性 / 模型形式限制 / 交付物与英文写作负担 / 96h 时间可行性 /
   论证空间」六维给每道题打分（每维一句依据），推荐 1–2 道。
   不要用"历年哪题 O 奖多"打分——那主要反映参赛队数。

我们的情况：【3 人，各自擅长……】

题面如下：
【粘贴六道题】
```

## 1. 单题深挖：Stage 2–3

```
我们选了【X】题。请按顺序输出，不要跳步：

一、Task 卡片：每个 Task 的输入 / 输出 / 约束 / 目标，以及它依赖哪个前序 Task 的结果。
二、数据诊断：逐条列「事实 → 出处 → 建模含义」。必须覆盖：
    观测是否独立（同一对象多条记录？）、要估计的量在数据里有没有观测（没有就不是监督学习）、
    多个数据源口径是否一致、同一类别是否有多种写法、时间序列验证会不会泄漏未来信息。
三、候选模型：每个 Task 至少两个结构不同的候选，写清为什么选、为什么放弃另一个。
    必须满足题面的模型形式限制。从最简模型开始，说明之后逐步加入哪些因素。
四、验证计划：每个模型用什么检验（量纲、极限情形、与数据/文献比对、交叉验证、灵敏度）。
```

## 1B. 按题型深挖（接在第 1 条后面用）

### 1B-① continuous_dynamics
```
1. 写出最简的守恒/速率方程，说明每一项的物理/生物含义与单位。
2. 列出题面点名的每个影响因素，逐个说明如何进入方程（不能用一个常数代替题面说会变的量）。
3. 参数来源：哪些可从公开数据/文献标定，标定方法是什么。
4. 数值解法（solve_ivp + rtol），以及非负性、守恒等自检。
5. 灵敏度：哪个参数最影响结论，给出扰动范围的依据。
```

### 1B-② discrete_optimization
```
1. 符号级写出决策变量、目标函数、约束；先给单目标小规模版本。
2. 多目标时给 Pareto 前沿和选择折中解的理由，而不是单一"最优"。
3. 与现行做法或贪心基线比较，量化提升。
4. 启发式算法要写清编码、参数、停止规则，多次运行报告区间。
```

### 1B-③ data_inference
```
1. 先做可解释基线（线性/逻辑回归或朴素预测），再上复杂模型，说明提升多少。
2. 验证：按时间切分或留出集，报告 RMSE/R²/准确率与预测区间；标准化只用训练集拟合。
3. 解释：特征重要性/SHAP，给出读者能用的结论。
4. 若要估计的量没有观测（如投票数），改用约束反推，并给一致性与不确定性度量。
```

### 1B-④ network_systems
```
1. 定义节点与边，边权的含义与单位。
2. 结构指标（中心性等）或网络流/仿真模型，说明回答题面哪个问题。
3. 情景：节点/边失效、需求变化；与"不考虑网络"的基线对比。
```

### 1B-⑤ evaluation_policy
```
1. 指标体系：每个指标的含义、方向、数据来源。
2. 赋权方法的选择理由（主客观结合要说明为什么）。
3. 必须再有一个能回答"如果……会怎样"的模型（预测/优化/机理）做情景比较——不能只交一张打分表。
4. 权重灵敏度：排名是否稳定。
5. 面向题面读者的政策建议（可执行、有数据支撑）。
```

### 1B-⑥ simulation_stochastic
```
1. 规则表：每条规则对应的现实机理。
2. 收敛检查、多次运行的均值与区间。
3. 参数扫描，找出临界点。
```

## 2. 求解与结果呈现：Stage 5–7

```
对 Task【i】：
1. 先跑最简版本，给出数值结果并做恒等式/量纲自检，打印关键中间量。
2. 结果写进 results/Ti_*.json（后面论文里的数字从这里取，不要手抄）。
3. 出图用英文标签、带单位，图题写结论（例 "SOC falls fastest under video streaming at 0 °C"）；
   不用双纵轴；灰度打印可分辨。
4. 每张图后写一段 "This means ..." 的解读。
5. 灵敏度：扰动哪些参数、多大、结论变不变。
6. Strengths & Weaknesses 各 3 条，具体到证据；Weaknesses 里如果有"没考虑 X"而 X 是题面要求的，
   那不是局限，是没做完——回去做。
```

## 3. Summary Sheet：Stage 8

```
按 O 奖论文的规律写 Summary（最后写，一页内）：

- 标题：两段式，"意象/问题: 方法或对象"。
- 开场 1–2 句背景（含一个具体事实），立刻转到 "We develop ..."。
- 一句话总述整体框架（几个模型、各干什么）。
- 逐 Task：方法 + 关键数值结论（带单位/场景）+ 一句解读。
  O 奖 Summary 数字个数中位约 9 个；不要只写方法不写结果。
- 灵敏度/验证的结论（不是"做了"，是"结论不变/误差 X%"）。
- 题面要 letter/memo 就加一句写给谁、核心建议。
- 约 400–500 词；不复述题目（COMAP 明确判为弱摘要）；不放独立公式块。
- Keywords 3–6 个：对象 + 方法 + 模型名。

正文材料：【各 Task 的模型名、关键数值、灵敏度结论、letter/memo 读者】
```

## 4. Letter / Memo：Stage 8

```
写一份【letter / memo】给【题面原文中的读者】，篇幅【题面原文，如 one page】。
格式：
  MEMO 用 To / From: Team #【控制号】 / Date / Subject 抬头；Letter 用 Dear ...,
  1 句目的 → 2–4 条带数字的发现 → 编号建议（动词开头、可执行、有量级）→ 取舍与风险 → 落款只写控制号。
要求：不出现公式和自造缩写；每条建议都能在正文找到支撑结果；不写学校和姓名。
材料：【关键结论与数字】
```

## 5. 提交前终审：Stage 9

```
请逐条核对并给出「通过/不通过 + 证据」，任一不通过就不要提交：

COMAP 规则（以当届 instructions 为准）
□ 第 1 页是 Summary Sheet（Problem Chosen / Year / Team Control Number），没有封面
□ 整份解答 ≤ 25 页（Summary、目录、正文、letter/memo、参考文献、附录、代码都算）
□ Report on Use of AI（如用 AI）在 25 页之后
□ 每页页眉有控制号与页码；正文字号 ≥ 12pt；全英文
□ 任何地方没有学生、导师、学校名称；PDF 属性里没有作者名
□ 文件名 = 控制号.pdf，< 25 MB
□ 题面要求的 letter/memo/report 都在，读者、篇幅符合题面
□ 所有外部来源有 inline citation 与参考文献；非自制图片在原位标注出处
□ AI 工具在正文引用处标注、在参考文献列出；AI 报告逐条给工具、版本、query、output

内容
□ 每个 Task 都有数值结论、图、解读
□ Summary 与正文每个数字一致，能在结果文件里找到
□ 有灵敏度/稳健性；C 题有验证指标
□ AI 生成的参考文献逐条打开核对过

（装了 skill 时直接跑 scripts/check_compliance.py，上面能机器判的项它都查。）
```

## 6. 纠偏指令

> 当 AI 给出的方案"看起来很高级但说不清为什么"时用。

```
停一下。对你刚才给出的每个方法回答：
1. 把这段方法描述换到另一道完全不同的题上，它是否照样成立？如果是，请从题目本身重新推导。
2. 它的前提假设是什么？题目数据满足吗？用什么检验验证？
3. 题面有没有限定模型形式？这个方法满足吗？
另外：合理的简化 + 理由 + 灵敏度检验，比堆复杂模型更好。不要因为"不够高级"就推翻可用方案。
```
