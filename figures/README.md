# 图表模板（英文论文）

**图是主要得分位，不是装饰。** 美赛评委第一轮主要读 Summary 和翻图；O 奖论文图数中位约 **14 张**、表约 5 张
（`competitions/mcm/empirical.json`）。25 页上限意味着每张图都要"一眼读懂"，不能靠正文解释补救。
**美赛论文的图里不要出现中文**：标签、图例、刻度、注释全部英文。

```bash
python figures/starter.py                    # 六段全出（内置合成数据），输出到 figures_out/
python figures/starter.py --only 2           # 只出相关矩阵那段
python figures/flow_pptx.py --preview        # 出可编辑 pptx（总览 + 每个 Task 模板），并渲染预览
```

| 文件 | 是什么 | 改不改 |
|---|---|---|
| `mcm_style.py` | 样式模块：英文衬线字体（与正文 newtx/Times 一致，缺字体时回退 STIX/DejaVu）、配色、字号、流程图与相关矩阵 helper、保存并出灰度校样 | 别改 |
| `starter.py` | **拿来就改的起手式**：描述统计三联 / 相关矩阵 / 拟合+残差 / 灵敏度龙卷风 / 分组趋势+个体轨迹 / 总览流程图。只换 `load_data()` | **拷进项目改** |
| `flow_pptx.py` | 生成**可编辑 pptx** 的总览图（Introduction 的 "Our Work"）与每个 Task 的流程图模板 | 改文字与框 |

**赛前先裸跑 `starter.py` 一次。** 它同时是环境自检：matplotlib、字体回退、Pillow（灰度校样）哪一样没配好都会在这里报出来。

守卫测试在 `tests/test_figures.py` 与 `tests/test_glyph_safety.py`：色标是否钉在 [-1,1]、折线箭头两端是否平行、轴标签是否为空、第 9 个系列是否报错、pptx 的连接线是否两端都绑住、图上的字符字体里有没有字形。这几项的共同点是**画错了不报错**。

## 流程图为什么走 pptx 而不是代码

其余的图都是"数据决定长相"——数据一换图自己就对了，所以代码是最好的载体。流程图不是：它的内容是**人的判断**（分几步、哪一步反馈到哪一步），96 小时里跟着模型改三四遍，每次都是挪一个框、改几个词。

这种编辑循环里 pptx 有一条别的格式没有的优势：**connector 的两端锚在形状上**，拖动框，箭头自动跟随。队友用 PowerPoint 或 WPS 双击就能改。

| | PPTX | SVG | matplotlib |
|---|---|---|---|
| 拖框改字 | 原生形状 | Inkscape 可改 | 改代码 |
| **箭头跟着框走** | **是** | 否 | 否 |
| 进论文 | 另存为 PDF（矢量） | 直接进 | 直接进 |

幻灯片尺寸设成 **20×15 cm**，"另存为图片"导出的就是插图该有的比例。matplotlib 版（`starter.py` 第 6 段）保留，用于不装 Office 或要和其它图严格同风格的情况；两版取同一套 `FLOW_TINTS`。

**已知限制**：`flow_pptx.py` 只生成文件、不渲染。`--preview` 把 pptx 里的真实坐标读回来用 matplotlib 重画一张 PNG 并量文字有没有挤出框，但折线连接器在预览里一律画成直线。**长相以 PowerPoint/WPS 里打开为准。**

## 灰度可读：低成本保险

灰度打印后颜色只剩明度。本模块配色的相对亮度：

```
violet 0.073 · green 0.162 · blue 0.188 · red 0.216
orange 0.278 · aqua 0.323 · magenta 0.340 · yellow 0.435
```

最难分的几对：aqua↔magenta ΔL=0.017、blue↔green 0.025、blue↔red 0.028——打印出来基本同色。所以第二通道是**默认而非选项**：

```python
ms.series_kw(i, "line")   # → 颜色 + 线型 + 标记，捆在一起
ms.series_kw(i, "bar")    # → 颜色 + 填充网格
```

`ms.save()` 顺手出一份 `_gray.png`。第二通道成本接近零（男性色盲约 8%），但它**不是获奖条件**，别为它牺牲颜色的表现力。

## 流程图：四条规矩

1. **层级靠位置和箭头，不靠颜色。** 颜色只标角色（输入/处理/建模/校验/交付）。
2. **箭头连边中点，不连中心**（`b.s` → `b2.n`），否则扎进框里压住文字。多条边汇进同一个框时用分数锚点 `top(0.1) / top(0.5) / top(0.9)` 摊开。
3. **反馈边画虚线**，`angle=(180, 90)` 走直角折线绕在主干外侧。
4. **框里写"做什么"，不写"用什么"。** "Cross-task consistency check" 比 "Consistency module" 有信息。

`flow_arrow(angle=(a, b))` 两端方向平行时折线没有交点，matplotlib 会画出乱线且不报错——helper 直接拦住。

## 相关矩阵：为什么不能随手 imshow

`imshow(C)` 会按数据范围自动拉伸色标：相关系数都在 0.3–0.9 时中点落到 0.6，**图上"看起来中性"的格子其实是强正相关**，且不报错。`ms.corr_heatmap()` 把 `vmin=-1, vmax=1` 写死，超范围输入直接报错。这张图在灰度下必然丢符号，所以**数字标注就是它的第二通道**，`annot_min` 别关。

## 硬规矩

1. **绝不用双纵轴。** 量纲不同就画两张图。
2. **坐标轴必须带单位。** `ms.finish()` 强制 `xlabel`/`ylabel` 非空；无量纲写 "(dimensionless)"。
3. **≥2 个系列必须有图例**；单系列不要图例框。
4. **不要每个点都标数字。** 只标最值、拐点、结论点（`ms.annotate_value()`）。
5. **图题写结论**："SOC falls fastest under video streaming at 0 °C"，不写 "SOC curve"。
6. **顺序色单一色相由浅到深，发散色中点是灰。** 不用彩虹色。
7. **最多 8 个系列，散点/气泡最多 3 个。** 超了 `series_kw` 直接报错——该分面或合并成 "Other"。
8. **非自制的图（引用的地图、照片、他人图表）在图题里标注出处**（COMAP 规则）。

## 开发中被实测纠正的三处

- **填充网格自己盖住自己**：`edgecolor` 与 `facecolor` 同色时 hatch 线看不见，灰度稿整根条糊成一块。改用画布色画网格。
- **形式选错**：67 根堆叠条回答不了任何问题，按类型聚合成 2 根宽条才有信息。
- **标记密度**：900 个点打 900 个标记就成了噪声。`series_kw(..., n_points=n)` 自动稀释到约 12 个并错开起点。

## 配色出处

分类色板取自经验证的八槽固定顺序色板：相邻对最差 CVD ΔE 9.1、正常视觉 ΔE 19.6（OKLab ×100）。散点这类"任意两两同框"的形式只有前三槽能全对通过。**槽的顺序本身就是色盲安全机制**，别重新排。
