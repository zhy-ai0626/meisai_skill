# Repository instructions

This repository contains the `mcm-icm` skill (美赛 MCM/ICM workflow). When working inside this repository, act as a maintainer: do not start the ten-stage contest workflow merely because modeling-related files are present.

Before starting development work, read `docs/PROJECT_MEMORY.md` (current status, next steps, local environment, corpus location). Update its status and next-step sections before ending a session. `CLAUDE.md` only imports this file and that memory file, so Claude Code and Codex share the same notes.

## Sources of truth

- `SKILL.md` defines runtime behavior and trigger boundaries.
- `references/stage_00_kickoff.md` through `references/stage_09_review.md` contain stage details and must be loaded lazily at runtime.
- `competitions/mcm/` contains MCM/ICM rules, heuristics, overlays, paper structures and the empirical layer.
- `templates/shared/decision_log.json` is the canonical persistent-state template.
- `config/rubric.json` is the single source of the L1 rubric; the tables in `references/*.md` are generated by `scripts/render_rubric.py --write`.
- `agents/openai.yaml` and `skills/mcm-icm/SKILL.md` are packaging metadata or thin discovery shims. Do not duplicate the workflow into them.

## Maintenance rules

- Preserve the trigger boundary: this skill is for COMAP MCM/ICM contest work, not CUMCM, HiMCM, generic data analysis or ordinary paper review.
- Treat official contest rules as time-sensitive. Keep a verification date and primary source in `competitions/mcm/current_rules.md`; COMAP's current instructions and the current problem statements always override repository guidance.
- Treat `empirical.json` and `winning_patterns.md` as observations, never official thresholds or award predictors. Every `anti_patterns.md` entry that cites judging or rules must name a publicly checkable source.
- Rebuild `competitions/mcm/empirical.json` only with `scripts/build_empirical.py` and a corpus whose award status was checked against COMAP's official results; record sample sizes and sources in `competitions/mcm/README.md`.
- Keep user artifacts relative to the user's working directory (`state/`, `results/`, `figures/`, `paper_workspace/`, `paper_output/`). Resolve repository resources relative to the installed skill root.
- Keep `SKILL.md` concise and dispatch stage-specific detail into `references/`.
- Do not add runtime claims about awards, token savings, or elapsed time without a reproducible benchmark.
- When changing behavior, update the README, tests, state schema, and relevant competition docs together.
- Do not vendor papers, problem statements, paid course material, or binary assets without a clear redistribution license. Keep runtime dependencies and external-source boundaries accurate in `THIRD_PARTY_NOTICES.md`.
- Never commit API keys or tokens (for example a MinerU token used to parse the corpus); pass them through environment variables.

## Verification

Run the checks proportionate to the change. Before a release, run all of them:

```bash
python -m compileall -q scripts templates/shared/code_starter figures
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/doctor.py --skip-tools
python scripts/render_rubric.py --diff
git diff --check
```

With a TeX distribution installed, also run `python scripts/doctor.py --require-renderer` (it compiles `templates/latex/mcm/smoke.tex`).

Runtime evaluation prompts should explicitly invoke `$mcm-icm`. Negative-trigger tests should confirm that CUMCM requests, generic model-selection and non-competition writing requests do not invoke it.
